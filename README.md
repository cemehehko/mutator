# mutator

Просмотр датников TLL (`file://`, `*.dat`) — в окне и в терминале. Таблица
сообщений с выбранными полями, листание гигабайтных файлов, фильтр и поиск
Lua-выражением как у `tll-read -f`, разбор сообщения по полям с hex. Файлы
читает libtll, фильтр выполняет tll-lua — поэтому видно ровно то, что видит
tll-read. Правки — значения полей и состав потока (удаление, вставка, смена
типа) — готовятся в окне и фиксируются через tll-patch — в новый файл или на
место исходника с бэкапом. Другие форматы подключаются бэкендами извне
(`io::register`). Рядом с просмотрщиком живёт агент: диалог с
LLM (OpenAI-совместимый API), который читает датник инструментами, собирает
фильтр и готовит правки — каждую человек подтверждает сам.

Как устроено и почему — в [ARCHITECTURE.md](ARCHITECTURE.md): карта модулей и
договорённости. Детали модулей — в их doc-комментариях.

## Что умеет

- Таблица: seq, тип сообщения и поля по путям (`header.status`, `price`…);
  пресеты колонок, свои — в `~/.config/mutator/presets.toml`.
- Листание любого объёма: окно строк вокруг экрана, прыжки по seq, `+N`, `-N`,
  в начало и в конец; индекс строк и счётчики типов строятся в фоне.
- Несколько файлов одним видом: `a.dat+b.dat` — склейка, `текущий.dat-3` — файл
  и 3 более старых той же ротации; фиксация правит каждый файл отдельно.
- Фильтр по типам и Lua-выражению, поиск вперёд и назад внутри фильтра.
- Деталь: дерево полей с путём в формате tll-patch, типом и смещением, hex с
  подсветкой байт поля.
- Три вида одного состояния: окно, TUI в окне (F2), терминал (`--tui`).
- `--dump`: YAML как у tll-read — для сверки и скриптов; `--stat` — сводка по
  файлу, сессия (правки и transform) применяется, изменённые поля помечены.
- Сессии: фильтр, поиск, колонки, место в файле, деталь и окно запоминаются по
  имени файла и возвращаются при следующем открытии (`--fresh` — без них).
- Окно открывается и без файла: берёт последний, иначе спрашивает; файл можно
  перетащить в окно или выбрать в меню «Файл → Последние файлы» (macOS).
- Агент (F3): спрашивает о файле по-русски, ищет и читает его сам; правки
  готовит пачкой — одна сводка и одно подтверждение на всю пачку. Настройки
  адреса, ключа и модели — на экране агента; без них агент просто не отвечает.

## Сборка и запуск

Нужны libtll (грузится при запуске, путь — `MUTATOR_LIBTLL`) и, для фильтра, модуль tll-lua.

```
cargo build --release
export MUTATOR_LUA=../tll-lua/build/tll-lua   # если tll-lua не в системе
./target/release/mutator FILE.dat             # окно (без FILE — последний файл)
./target/release/mutator FILE.dat --tui       # терминал (в сборке без GUI — по умолчанию)
scripts/bundle-macos.sh                       # mutator.app: окно без терминала
./target/release/mutator FILE.dat --dump -s 100:+3 -f "name == 'NewOrder'"
```

Клавиши: ↑↓ PgUp/PgDn Home/End, Enter — деталь (`x` hex, `i` типы полей), Tab — фокус, `f` фильтр, `t`
типы, `/` `?` поиск, `n`/`N`, `g` переход, `c` колонки, `p` пресет, ←/→ колонки
полей, `r` — перечитать файл, F2 — TUI, F3 — агент, F1 — справка по всем возможностям, `q` выход.

## Проверки

`scripts/check.sh` в Docker — всё разом: тесты, документация, связь
договорённостей с тестами, порог покрытия. Эталоны разбора — `scripts/golden.py`.

## Ограничения

- Сеть нужна только агенту: без адреса и ключа всё остальное работает офлайн.
- Без tll-lua фильтр и поиск недоступны; просмотр и листание работают.
- Растущий файл (`*.current.dat`) — снимок на момент открытия.
- Интерфейс на русском, тема тёмная.
