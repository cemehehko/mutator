# Правила для агентов в этом репозитории

Порядок взят из black-d и подогнан под этот проект.

## Уровни описания

Один замысел описан на нескольких уровнях, от общего к точному. Каждый уровень
говорит своё и не пересказывает соседей:

| Уровень | Где | Что там |
|---|---|---|
| Сценарии | `SCENARIOS.md` (~22 строк; один-два сценария, не больше) | зачем утилита: ситуации пользователя и желаемый исход, id `scn:…` |
| Требования | `REQUIREMENTS.md` (~115 строк) | что утилита делает для пользователя: правила поведения, id `req:…` |
| Бриф | `README.md` (~70 строк) | зачем, платформы, сборка, ограничения |
| Карта | `ARCHITECTURE.md` (~300 строк) | модули, потоки, договорённости с id `agr:…` |
| Модуль | `//!` в начале файла | как устроен модуль и почему так |
| Тесты | `#[cfg(test)]`, `tests/` | поведение; имя теста — утверждение по-английски |
| Ручные | `MANUAL.md` (~30 строк) | что не накрыть автотестом: шаги и исход, id `man:…` |
| Код | `///` и сам код | контракт элемента |

Машина проверяет связи между уровнями:

- **Сценарии ↔ требования ↔ договорённости ↔ тесты и руки** — `scripts/req.sh`:
  `scn:` держится `req:…`, требование — `agr:…` и хотя бы одним тестом через
  них; договорённость со словами «руками»/«настоящий терминал» — пунктом в
  `MANUAL.md` (`man:…`); метки уровней — только в своих файлах.
- **Договорённость ↔ тест ↔ код** — `scripts/trace.sh`. Метка `` `agr:id` `` в
  `///` над `#[test]` (в `src/` или `tests/`) — тест, который её держит; в
  `src/` в другом месте — код, который её реализует. Без теста — только с
  пометкой «Без теста: причина» в пункте договорённости.
- **Комментарий ↔ код.** Имена в doc-комментариях — ссылками `` [`Имя`] ``:
  переименование ломает `cargo doc`.
- **Карта ↔ модули ↔ файлы** — `scripts/levels.sh`. Каждый модуль `src/` назван
  в таблице модулей `ARCHITECTURE.md`, каждый файл папки — в `//!` её `mod.rs`.
- **`//!` ↔ поверхность.** Что файл открывает наружу, названо в его `//!`.
- **Тесты ↔ карта** — `scripts/cover.sh`: покрытие по модулям карты, порог
  только поднимается; модуль без порога пишет в `//!` «Без теста: причина».

**Меняешь поведение** — сначала пункт в `REQUIREMENTS.md` (зачем — сценарий в
`SCENARIOS.md`); пункта нет или спорно — сначала спроси пользователя, потом код.
Дальше: тест с меткой договорённости (у теста и кода), `//!` модуля; меняется
карта или договорённость — `ARCHITECTURE.md`, идея — README.

**Разбор и формат значений** сверяются с python-tll: эталоны — `scripts/golden.py`
(`tests/data/*.dat` + `*.json`). Меняешь разбор — пересоздай эталоны и убедись,
что расхождение — в нашу пользу, а не в их.

## README.md — бриф, а не документация

Тест перед любой строкой README: это идея («фильтр — как у tll-read») или деталь
реализации («точка индекса на 1024 сообщения»)? Второе — в README не писать, его
место — `ARCHITECTURE.md`, `//!`, тесты.

**Бюджет.** Файлы уровней — соразмерно глубине: вверх короткие «зачем», вниз
длинные «как». Считает `scripts/budget.sh`, назначение — только вниз (как
пороги `cover.sh` — только вверх). Превышение — сначала сократи: перенеси
деталь уровнем ниже или удали устаревшее.

**Актуальность.** Изменение поведения, платформ или стека — повод пройтись по
README и `ARCHITECTURE.md`: устаревший текст хуже отсутствующего.

## Прочее

- libtll и tll-lua — внешние: исходники рядом (`../tll`, `../tll-lua`), на маке —
  Homebrew-сборка tll и `TUI_PATCH_LUA` на собранный tll-lua.
- Проверки целиком — `scripts/check.sh` в Docker (colima: проброшен только
  `$HOME`); быстрые `cargo test` можно и на хосте.
- Живые файлы — на стендах (`ssh 141`, `ssh 121`, каталоги mu0); образцы в корне
  репо в git не попадают.
- Отвечать пользователю по-русски.
