# Архитектура

Уровень под требованиями (`REQUIREMENTS.md`) и брифом (README): карта модулей,
потоки данных и договорённости.
Как устроен каждый модуль — в его `//!` (`cargo doc --document-private-items`).

## Карта

Одна библиотека `tui_patch`, бинарник `mutator` (`src/main.rs`): окно (egui), `--tui` —
терминал (в сборке без GUI — всегда), `--dump` — печать YAML как у tll-read. Файл читает libtll; интерфейс и
чтение говорят только каналами: команды туда, события обратно.

```
   окно egui ──┐     ┌── TUI в окне (F2) ── терминал --tui
   ui/table,   │     │   ui/tui: одна сетка знаков
   detail, bar │     │
               ▼     ▼
            desk.rs: окно строк, фильтр, поиск, деталь, ввод
                  │ Cmd ▲ Ev
                  ▼     │
            data/: воркер окна + фоновые индекс, фильтр, поиск
                  │  куски seq параллельно, свой контекст на поток
                  ▼
            tll/: file://, lua+file:// и линки через libtll + tll-lua
            decode/ + scheme.rs: тело по схеме → дерево полей
```

| Модуль | Отвечает за |
|---|---|
| `io/` | фасад чтения и записи: бэкенд по файлу и сборке, ленивые контексты, загрузка библиотек, линк в спул |
| `app.rs` | запуск: аргументы, выбор режима — окно, терминал, печать; в библиотеке для внешних бэкендов |
| `tll/` | бэкенд TLL — FFI к libtll: контекст, чтение файла с seq и Lua-фильтром, перенос схемы, линк по url |
| `scheme.rs` | схема в своих типах: сообщения, поля, enum, bits, пути полей |
| `decode/` | тело сообщения по схеме → дерево [`Node`] и текст значений как у tll-read |
| `lua.rs` | код `tll_filter` для префикса `lua+` — тот же, что строит tll-read |
| `lua_highlight.rs` | подсветка Lua для редактора: токены → цвета, для окна и TUI |
| `range.rs` | границы `-s` и перехода: `SEQ`, `+N`, `-N` |
| `dump.rs` | `--dump`: YAML как у tll-read, `--stat`, цвет, мутации сессии |
| `data/` | воркер: окно строк, разреженный индекс, фильтр и поиск по кускам |
| `columns.rs` | колонки и пресеты (встроенный «orders», свои в `presets.toml`) |
| `desk.rs` | состояние просмотрщика — одно на все виды; клавиши и строки ввода |
| `session.rs` | сессия файла: фильтр, поиск, колонки, место, деталь, окно — по имени файла |
| `recent.rs` | последние открытые файлы: список в `recent.toml`, последний существующий |
| `spec.rs` | спека открытия: один файл, склейка `+`, файлы ротации назад `-N` |
| `edit/` | правки полей и состава потока, запись их по схеме, фиксация в новый файл или с бэкапом |
| `agent/` | диалог с моделью: настройки и диалоги на диске, клиент к LLM, инструменты чтения датника |
| `markup.rs` | разбор ответа модели на блоки (`Block`) и спаны (`Span`), общий для окна и TUI |
| `serve/` | сервер для тестировщиков: читающие инструменты агента по REST и SSE (фича `rest`), MCP по HTTP и stdio (`mcp`), веб-UI — страница `web/index.html` (`wui`) |
| `ui/` | окно: таблица, деталь, панель; `ui/shell.rs` — оболочка (заглушка, смена файла, перетаскивание), `ui/menu.rs` — родное меню macOS; `ui/tui/` — сетка знаков и терминал; `ui/agent/` — экран агента |

`ui/` режется по деталям, как в black-d: таблица, деталь, панель, раскладка
колонок, тема; страница окна только собирает. TUI — подсистема со своей сеткой,
но тем же `Desk`.

## Потоки

- **Окно строк.** `Desk` держит строки вокруг экрана с запасом; у края запаса
  просит воркер дочитать (`Extend`), дальний край обрезает. Прыжок (Home, End,
  `g`, полоса прокрутки, найденное) — новое окно с новым поколением; устаревшие
  ответы отбрасываются, очередь воркера сжимается до последнего прыжка.
- **Индекс.** Сразу после открытия, параллельно по кускам seq: число строк,
  контрольные точки (строка, seq) и счётчики типов. До индекса номера строк
  нет, полоса прокрутки — по seq.
- **Фильтр.** Код Lua как у tll-read; скан по кускам, найденные seq растут
  префиксом в общем `Matches`, таблица показывает их сразу. Вид фильтра — окно по
  номеру строки в `Matches`.
- **Поиск.** То же выражение, пересечённое с фильтром; куски растут от выбранной
  строки, первое совпадение в нужную сторону — ответ.
- **Линк.** Канал пишется в спул своим потоком (`io::link`); вид открывается на
  спуле, когда линк стал Active, и читает его как файл; рост спула — `Cmd::Tail`:
  индекс и фильтр дописываются хвостом.

## Договорённости

У каждой — id: им помечены держащие её тесты и код; `scripts/trace.sh` следит,
чтобы ни одна не осталась без теста, а метка — без договорённости. «Без теста» —
осознанное исключение с причиной.

### Данные

- `agr:same-as-tll-read` — **Значения — как у tll-read.** Разбор и `--dump`
  сверяются с python-tll на эталонах и живых файлах: Decimal, время, enum,
  строки, кавычки YAML.
- `agr:lua-like-tll-read` — **Фильтр — код tll-read.** `tll_filter` строится
  строка в строку как `tll-read -f/--message`; выполняет его tll-lua, не мы.
- `agr:backend-choice` — **Бэкенд — по файлу и сборке.** `--backend`, иначе бэкенд
  открытого файла (`Info`), иначе первый бэкенд, узнавший начало файла.
- `agr:io-facade` — **Остальной код не знает бэкенда:** всё — через `io/`.
  Без теста: устройство модулей, его держит сборка каждой фичи по отдельности.
- `agr:backend-dlopen` — **Библиотеки бэкендов грузятся при открытии**, не
  линкуются; путь канонизируется — вторая копия раздвоила бы журнал и модули.
- `agr:backend-plugin` — **Внешний бэкенд — через `io::register`** до
  `app::main`: свой Lua-диалект, печать `--dump` и библиотека; основная репа о
  нём не знает.
- `agr:dump-first` — **`--once` — одно сообщение.** `--dump --once` печатает
  первое сообщение выборки, включая выборку с пропуском (`+N:`).
- `agr:dump-color` — **Цвет — как у tll-read.** Красит только `Painter`,
  эталонный вывод — без ANSI; `--color auto` — только когда вывод в терминал.
- `agr:dump-stat` — **`--stat` — meta-проход.** Границы seq, всего сообщений
  и счётчики типов без чтения тел.
- `agr:dump-mutations` — **`--dump` показывает сессию.** Фильтр, правки и
  включённый transform применяются (правки поверх transform), изменённые поля помечены
  `# в файле: <старое>`; при transform фильтр едет как в виде — пост-эвалом
  (`agr:filter-post-eval`), без — кодом в канале, как у tll-read. `--fresh`
  читает сырой файл.
- `agr:transform-shadow` — **Вид показывает тело после мутатора и отмечает
  отличия от файла.** При transform чтение тел идёт `lua+file://` без пресета
  фильтра, правки — поверх: тела едут в вид уже прогоными — как на фиксации. Диф мутатора
  считается второй читкой: те же seq читаются сырыми из файла и прогоняются
  через пару `lua+direct` постом в direct-slave (синхронно). Отличившиеся поля —
  красные, в подсказке — значение из файла; поменял seq — строка красная, в
  деталях рядом исходный seq (правки адресуются им); выброшенное мутатором
  сообщение в вид не попадает вовсе. Ошибка мутатора не ломает вид и видна в строке
  состояния. Фильтр и поиск едут по правленному потоку с пост-эвалом
  (`agr:filter-post-eval`), фиксация — всеми правками поверх transform (ручная
  правка поверх мутации скрипта).
- `agr:filter-post-eval` — **Фильтр и поиск едут по правленному потоку.** Чтение
  — transform, поверх правки; типы отбираются в Rust по msgid (meta-оптимизация живёт
  только для отбора одних типов), выражение — пост-эвалом парой `tll_filter`
  (`lua+direct`, `Transformer::filter`) поверх прогоных тел. Transformer — один
  на поток-воркер (`chunks::run_state`), не на кусок. Масс-скан — по сырому
  потоку.
- `agr:bad-message` — **Сломанное сообщение не роняет ни разбор, ни экран.**
  Ошибка — у своего узла; соседние поля видны.
- `agr:missing-field` — **Поля нет в типе — ячейка пустая**, в фильтре — `nil`
  по правилам Lua.
- `agr:patch-path` — **Путь поля — в формате tll-patch** (`header.status`):
  деталь показывает его, колонка добавляется по нему, правка адресуется им.
- `agr:tll-lifecycle-lock` — **Создание и удаление каналов и контекстов libtll —
  под общим замком**: счётчики ссылок логгеров в libtll неатомарны. Чтение идёт
  параллельно.
- `agr:glue-spec` — **Спека — один или несколько файлов.** `a.dat+b.dat` —
  склейка в указанном порядке; `prefix.current.dat-N` и `prefix.{seq}.dat-N` —
  файл и ещё N более старых файлов той же ротации рядом (ищем в каталоге по
  именам `prefix.{seq}.dat` и `prefix.current.dat`, как `_build_map` в rotate+;
  порядок — по номеру, current последним; меньше есть — сколько есть).
  Существующий буквальный файл бьёт толкование спеки; семантики «`+N` —
  следующий файл» нет.
- `agr:glue-parts` — **Склейка — части с восходящими диапазонами.** Открытый
  файл — упорядоченные части со строго восходящими непересекающимися
  диапазонами seq (инвариант тот же, что у карты rotate+; нарушение — ошибка
  открытия), схема — последней части, пустая (молодой `current.dat`) инертна.
  Окна, индекс, фильтр и поиск идут по всем частям: вперёд — продолжением с
  начала следующей, назад — справа налево, растущий хвост живёт в последней;
  сессия и журнал — по строке спеки как имени.

### Большие файлы

- `agr:anchor` — **Положение — сообщение, а не номер строки.** Номер появляется,
  когда готов индекс или в виде фильтра; до того листание и прыжки идут по seq.
  Возврат к сообщению (сессия, `g`) показывает его с третью экрана контекста
  выше (`At::Around`), а последнее — у нижнего края: окно, дочитанное до конца
  файла, не оставляет пустоты под последней строкой.
- `agr:reload` — **Растущий файл перечитывается по запросу.** `r` (или `↓`/`PgDn`
  на последней строке) переоткрывает файл на том же месте: курсор остаётся на
  прежнем seq (или ближайшем после него), окно — там, где было; а `End` с
  последней строки перечитывает и встаёт на новую последнюю. В строке
  состояния — сколько дописалось («+N строк»). Фильтр, поиск, колонки, правки и
  transform возвращаются из сессии.
- `agr:sparse-index` — **Индекс разреженный:** точка на 1024 сообщения, память
  не зависит от размера файла линейно по байтам.
- `agr:chunks` — **Долгое — кусками seq параллельно**, результаты по порядку
  кусков: префикс растёт ровно, поиск отдаёт ближайшее, не дожидаясь остальных.
- `agr:filter-streams` — **Фильтр показывает найденное сразу**, не дожидаясь
  конца скана; выбор возвращается туда, где стоял, когда скан до него дойдёт.
- `agr:ui-no-wait` — **Кадр не ждёт диска.** Всё чтение — в воркере и фоновых
  потоках. Без теста: это устройство каналов, а не поведение экрана.

### Линк

- `agr:link-spool` — **Линк — в спул, дальше — как файл.** Канал читается один
  раз и пишется датником; временный (`$TMPDIR/mutator-<pid>`) уходит с последним
  владельцем и при выходе, брошенные чистит следующий запуск; `--keep` — остаётся.
- `agr:link-tail` — **Хвост линка дописывается в вид сам**: индекс и найденное
  фильтром — за прежним концом, окно у края дочитывает; курсор и окно стоят — и
  на последней строке.
  Пока качается история, хвост спрашивают не чаще 10 раз в секунду, а воркер
  делает его один раз на пачку и после окна: `PgDn` не ждёт хвоста.
- `agr:link-open` — **Параметры открытия — каналу.** По умолчанию `mode=online`
  у stream и resolve, прочим — ничего (`mode` есть и у `lua+`); `o` — заново в
  новый спул, `r` — в тот же, с историей — `seq-data` с последнего. `--resolve`:
  сервер для `resolve://` и схем `sha256://` прямого url; свой `name` url — его.
- `agr:link-read-only` — **Линк только смотрят**: правка, фиксация, агент — отказ.
- `agr:link-state` — **Состояние линка видно всегда**: Opening/Active/Error/Closed,
  история или онлайн, ошибка libtll — в заголовке TUI, строке и заглушке окна, в
  терминале до вида. Сеть и `resolve://` — руками (`man:link-live`).

### Правка

- `agr:patch-overlay` — **Правки накладывает фасад `io`**: файл не меняется,
  `io::Reader` пишет правки в тела поверх потока любого бэкенда — после
  transform, так что правка ложится поверх мутации скрипта; каждая версия
  правок — свой снимок в памяти. Вид и фиксация накладывают разное
  (`agr:view-input-seq`).
- `agr:edit-encode` — **Правку пишет свой кодировщик по схеме**, без внешних
  модулей: текст значения — тот же, что показывает деталь, `decode(encode(s))
  == s`; семантика — команд tll-patch (`Field`, `Update`, `Insert`, `Remove`,
  `Clear`). Эталоны `tests/data/patch.json` и `stream.json` пишет настоящий
  tll-patch (`scripts/golden.py --patch`) — тела и поток совпадают.
- `agr:edit-checked` — **Значение проверяется до принятия**: воркер читает одно
  сообщение с кандидатом правок — значение, которое не записать, обрывает
  чтение; вставка собирается по схеме сразу, копия сверяется с исходником по
  полям. Не принятое — строка ввода возвращается, правка не создаётся.
- `agr:edits-in-session` — **Незафиксированные правки — в сессии файла**:
  отложенный `w`, перезапуск не теряет сделанного.
- `agr:commit-keeps-original` — **Фиксация не теряет исходник**: новый файл —
  исходник не тронут; перезапись — исходник в бэкап под свободным именем.
- `agr:stream-ops` — **Состав потока — команды в смысле tll-patch на входной seq.**
  Удаление — `Remove` (seq дальше −1) или `Clear` (дыра), смена типа —
  `Update` (тело целиком, правки полей вливаются в него), вставка — `Insert`
  перед seq. На seq одна операция; поле удалённого не правится. Подряд идущие
  seq файла с удалением одного рода или со сменой на один тип с одним телом
  сливаются в одну команду `from`/`till` (till исключён) — в yaml для показа.
  Вставка — перед живым seq или в дыру, в дыру одна, за последним seq нельзя:
  запись отдала бы её только в конце потока.
- `agr:view-input-seq` — **Вид — во входных seq.** Чтение с середины не знает
  сдвига от удалений и вставок выше, поэтому вид накладывает только правки
  полей и смену типа; удалённое остаётся строкой с пометкой, вставка —
  виртуальной строкой перед своим seq, рядом — seq после записи. Состав потока
  с перенумерацией накладывает только фиксация — с начала файла.
- `agr:seq-forecast` — **Последний seq — прогноз по правкам.** Без прохода:
  сдвиг перед seq — вставки в живые seq выше минус удалённые со сдвигом выше;
  удалён хвост — последний живой seq ищется чтением назад. Transform в прогноз
  не входит, и строка об этом говорит.
- `agr:commit-seq-check` — **Фиксация следит за seq, а не за числом**: проход
  запоминает настоящий последний seq; seq не больше предыдущего (дубль от
  transform) останавливает запись с местом — libtll такое не пишет.
- `agr:glue-commit` — **Фиксация склейки — по файлу.** Пишутся части с правками,
  с включённым transform и сдвинутые seq-меняющими правками ранних частей;
  каждая отдельно, одними и теми же правками (правки с seq не этой части в её
  потоке не срабатывают; вставки — только перед seq от начала части до начала
  следующей, в дыре между частями — у ранней), а кросс-частный сдвиг
  перенумерации запись вносит сама — поток части о правках «позади» не знает. Имена — по фактическим
  границам записанного: ротационная часть получает `prefix.{M}.dat` тем же
  ключом, что назван исходник; новым файлом — тег рядом (`prefix.{M}.patched.dat`
  и `x.patched.dat`, невидимы для rotate+), перезаписью — под пересчитанным
  именем с бэкапом исходника (растущая часть перезапись запрещает). Опустевшая
  часть файла-результата не оставляет: пустой нумерованный файл ломает rotate+
  (новым файлом — выхода нет, перезаписью — исходник в бэкап). Вставки
  адресуются seq сообщений вида — в дырах между частями их не бывает.
  Семья выходов сверяется с настоящим rotate+ руками (`man:glue-rotation`).

### Агент

- `agr:agent-same-desk` — **Агент работает на том же `Desk`, что и человек.**
  Читающие инструменты идут в своём потоке, а фильтр, поиск, переход, колонки и
  правки агент не делает сам: он шлёт действие по каналу, и его применяет вид —
  как если бы это нажал человек.
- `agr:agent-snap` — **Агент видит состояние вида через снимок.** Вид при каждом
  `poll()` отдаёт воркеру снимок (что открыто, фильтр, колонки, выбор) —
  читающие инструменты отвечают по нему, не опрашивая вид синхронно.
- `agr:agent-sync` — **Правки агент показывает один раз.** Посмотрев
  незафиксированные правки, агент отмечает их просмотренными — вид перестаёт
  присылать их в каждом снимке.
- `agr:agent-batch` — **Правка — пачка с одним подтверждением.** Один вызов
  `edit_messages` собирает всю пачку: записи проверяются по текущим значениям
  полей и записью по схеме до показа, человеку уходит одна сводка
  с количеством сообщений, и одно решение применяет или отбрасывает пачку
  целиком одним действием. Негодная пачка возвращается модели отказом —
  человека она не тревожит.
- `agr:agent-no-write` — **Агент не пишет файл.** Правки он только готовит:
  пачка проходит ту же проверку записью, что и ввод человека, и ложится в
  незафиксированные; фиксацию открывает и подтверждает человек (`w`, Enter).
- `agr:agent-one-turn` — **Один ход за раз:** пока модель отвечает или ждёт
  подтверждения, новый вопрос встаёт в очередь, а команды, меняющие активный
  диалог, пропускаются.
- `agr:agent-queue` — **Вопрос не теряется, пока модель отвечает.** Уточнение
  уходит в очередь с заметкой в ленте; когда ход закончится, накопленное
  склеивается в одно сообщение и ход запускается сам. Прерывание
  (`Ctrl+A`) на подтверждении — отказ с причиной: модель прекращает начатое.
- `agr:agent-gen` — **Правка агента не попадает в чужой файл.** При каждом
  переоткрытии (`Desk::reopen`) поколение файла растёт; правка несёт
  поколение на момент вызова, и устаревшую вид отбрасывает с сообщением —
  вместо молчаливой правки по устаревшей картине.
- `agr:agent-jsonl` — **Диалог пишется после каждого сообщения и обрыв не
  теряет ответ.** Дневник — строка меты и по строке на сообщение: переписка
  дописывается в конец, оборванная строка не читается. Частичный ответ при
  обрыве сети сохраняется в ленту, прежний цельный `.json` ещё читается.
- `agr:agent-tool-pairing` — **Вызов и его результат парные и идут подряд.**
  Результат инструмента сразу в лог как парный `Tool`; при сборке запроса
  непарные вызовы закрываются заглушками (лог не переписывается), а при обрыве
  хода заглушки дописываются в лог. Результат без исполнения — отказ и
  прерывание — тоже ложится парой.
- `agr:agent-loop` — **Воркер отвечает всегда.** Стрим модели идёт в отдельной
  задаче: куски и итог приходят каналами, команды `Confirm`/`Deny`/`Abort`
  читаются в любой момент. Прерывание снимает задачу и ставит флаг: остаток
  вызовов хода не исполняется, долгие сканы останавливаются между кусками.
  В ленте — только вопросы и ответы: результаты инструментов и ходы модели
  из одних вызовов остаются в дневнике и уходят модели, а человеку итог
  последнего инструмента виден в строке состояния, пока ход идёт.
- `agr:agent-frame` — **Кадр потока разбирается целиком.** Текст, вызовы,
  `usage` и `finish_reason` в одном кадре — каждая часть своим куском, ни одна
  не вытесняет другие: provod шлёт `usage` в каждом кадре, а вызов — вместе с
  `finish_reason`.
- `agr:agent-empty` — **Пустой ответ — ошибка, а не тишина.** Ход без текста и
  без вызовов кончается ошибкой с `finish_reason` и советом сменить модель
  (gemini-2.5 на сломанном вызове отдаёт пустой `content_filter`); текст,
  оборванный `content_filter`, — уведомлением.
- `agr:agent-progress` — **Фаза хода видна.** Воркер шлёт `Started` на каждый
  виток, куски и `Tool` перед каждым инструментом; вид держит фазу «ждём»,
  «пишет», «инструмент» с её временем. «Пишет» — пока куски идут: после 1,5 с
  тишины снова «ждём»; после инструмента к «ждём» приписан его итог
  (`schema_fields → 25 строк`). Анимация — чистая функция фазы и времени: точки
  переливаются, пока ждём, спиннер — пока идут данные или работает инструмент.
  Как это выглядит, проверяется руками.
- `agr:agent-retry` — **Повтор — только пока стрим не начался.** Соединение с
  таймаутом; на ошибку соединения и 429 запрос повторяется (по `Retry-After`,
  иначе экспоненциально), уведомляя интерфейс; после первого кадра ответа
  повторов нет — там только прерывание. Живой стрим держит idle-таймаут на
  кадр: общий таймаут убил бы длинный ответ.

### Разметка ответа модели

- `agr:markup-shared` — **Разбор ответа модели общий для окна и TUI.**
  `markup.rs` разбивает текст на блоки кода, списки, цитаты и обычные абзацы,
  а внутри — на спаны жирного, кода и ссылок; оба вида рисуют одну и ту же
  структуру, но своими средствами вывода.

### Вид

- `agr:open-without-file` — **Окно открывается без файла и меняет файл на ходу.**
  Без аргумента — последний существующий из `recent.toml`, нет — диалог выбора,
  закрыли — заглушка. Сменить: меню «Файл» (диалог, «Последние») или
  перетаскивание; смена строит `App` заново, сессия прежнего пишется; идёт
  фиксация — не меняем. `--tui`, `--dump`, `--stat` без файла просят его. Меню и
  диалог — только macOS, проверяются руками; остальное — `tests/shell.rs`.
- `agr:gui-detach` — **Окно не держит терминал.** Из терминала перезапускает себя
  потомком в своей группе процессов без ввода-вывода; родитель выходит сразу.
  Не отсоединяем: `--gui`, `--foreground`/`-F`, `--tui`, `--dump`, `--stat`,
  снимок (`MUTATOR_SHOT`), запуск не из терминала, файл не найден. Без терминала
  — `mutator.app` (`scripts/bundle-macos.sh`); «Открыть с помощью» из Finder нет:
  winit 0.30 не отдаёт событие открытия документа.
- `agr:session-by-name` — **Сессия привязана к имени файла** (у линка — к url),
  а не к пути: копия со стенда открывается с теми же фильтром, колонками и
  местом. Пишется при изменении и при выходе; `--fresh` — с чистого листа.

- `agr:detail-share` — **Высота детали — доля окна**, одна для окна и TUI и в
  сессии: `{`/`}` и сессия её задают, панель окна следует за ней (в том числе
  при пустой детали и после правки поля), а тянут границу — доля берётся из
  фактической высоты; в TUI (терминал, браузер) границу тянут мышью
  (`tui::split_at`).
- `agr:tui-same-data` — **TUI — другой вид того же `Desk`**: в окне (F2) и в
  терминале одни клавиши, один ввод, одно состояние.
- `agr:size-column` — **Размер сообщения — колонкой `#data`.** Имя совпадает с
  Lua-синтаксисом размера (`#data` — длина тела в байтах, `__len` в tll-lua),
  поэтому не пересекается с полем схемы `size` и подсказывает, как писать
  фильтр по размеру (`#data > 100*1024`). Колонка — псевдополе в общем списке
  `columns` (пикер `c` в [`Desk::open_columns`]), значение — `data.len()`
  сырыми байтами, прижато вправо; в пресет по умолчанию не входит, но допустима
  в своих пресетах и через агента `set_columns`. Правленное или изменённое
  transform'ом тело — клетка крашена как изменённая. Пикер `c` — список с
  галочками: клавиши — `agr:picker-keys`.
- `agr:picker-keys` — **Списки с галочками — единые клавиши.** Окна выбора
  типов (`t` в [`Desk::open_types`]) и колонок (`c` в [`Desk::open_columns`])
  — списки отметок: пробел переключает отметку под курсором, Enter и Esc
  только закрывают окно — типы применяют отмеченное, колонки ничего не
  меняют, — Home/End — начало и конец списка. Списки выбора одного пункта
  (удаление, смена типа, Enum/Bits) — не они: там Enter выбирает пункт.
- `agr:tui-grid` — **TUI — сетка: знак в своей клетке**, шрифт не сдвигает
  столбцы (из black-d).
- `agr:gui-lua-text` — **Код редактора Lua виден в окне.** Панель номеров строк
  занимает ровно свою ширину, а не всю: поле ввода не схлопывается в нулевую
  ширину, и его текст рисуется подсвеченным.
- `agr:repaint-on-event` — **Окно рисуется по событию воркера**, а не по
  таймеру; пока идёт фоновая задача — не чаще 10 раз в секунду. Без теста:
  перерисовку решает eframe.
- `agr:term-quiet` — **В терминале журнал — в файл**: stderr лёг бы поверх
  экрана. Без теста: нужен настоящий терминал.
- `agr:term-restore` — **Терминал возвращается в прежний вид** при любом выходе и
  панике. Без теста: нужен настоящий терминал.

## Проверки

`scripts/check.sh` — одна точка входа, в Docker (образ собирает tll и tll-lua из
`../tll`, `../tll-lua`): fmt, clippy, тесты (юнит, интеграционные на эталонах
`tests/data`), документация без битых ссылок, сценарии и требования
(`scripts/req.sh`), трассировка договорённостей, уровни описания и порог
покрытия по модулям карты. Порог только поднимается.

Эталоны пишет `scripts/golden.py` (python-tll); живой файл сверяется так же
(`MUTATOR_GOLDEN`). Замер на больших файлах — `examples/bench.rs`, файл для
него — `scripts/bigfile.py`.

### Сервер

- `agr:serve-same-tools` — **Операция сервера — инструмент агента.** Список и
  JSON-схемы — `build_tools`, исполнение — `tools::execute` на `ToolCtx` без
  вида (`acts: None`), в `spawn_blocking`; транспорты только переводят запрос
  и ошибку. Своих операций у сервера нет.
- `agr:serve-features` — **Транспорт — фича сборки:** `rest` (REST + SSE,
  `--serve ADDR`), `mcp` (rmcp, HTTP и stdio) и `wui` (страница на `/`) — обе
  поверх `rest`. Без фичи сервера бинарь о нём не знает, даже в `--help`.
- `agr:serve-wui` — **Веб-UI — страница без сборки** (`web/index.html` в бинаре,
  deb собирается без Node): вкладка «Просмотр» — вид (`agr:serve-view-desk`),
  «API» — формы по схемам `/api/v1/ops`, вызовы REST, итоги и линки — по SSE;
  своей логики просмотра и операций у страницы нет. Браузер — руками (`man:wui`).
- `agr:serve-view-desk` — **Вид браузера — `Desk` на сервере, свой на вкладку**:
  `POST /api/v1/views` открывает файл или линк в своём потоке, клавиши и щелчки
  (`…/input`) идут в `Desk::key` и `tui::apply`, как у терминала. Вид только
  смотрит (`Desk::view_only`): правка и фиксация — отказ в строке состояния;
  F2–F4 и `q` в браузере нет. Без подписчиков кадров 30 с — вид закрывается.
- `agr:serve-view-frames` — **Кадр — сетка `tui::frame`**: SSE `…/frames` шлёт
  первый кадр целиком, дальше — только изменившиеся строки (как терминал —
  клетки); на ввод — сразу, сам по себе — не чаще 10 раз в секунду: шапка
  живого линка иначе забивает туннель. Размер сетки задаёт браузер по окну.
- `agr:serve-mcp` — **MCP — те же операции.** `tools/list` — `ops::list`
  (подсказка read-only), `tools/call` — `ops::call`, долгие — ждём целиком;
  отказ — результат с `isError` и причиной. `/mcp` (streamable HTTP) есть только
  с токеном (`agr:serve-token`), без него — 404; `--mcp-stdio` — stdout только
  протокол, журнал — в stderr.
- `agr:serve-token` — **Токен закрывает весь сервер** (`--token`/`MUTATOR_TOKEN`,
  `--mcp-token`/`MCP_TOKEN` — то же): `Authorization: Bearer`, cookie или
  `?token=` (ставит cookie — так входит страница и её EventSource); без — 401.
  Без токена сервер слушает только loopback, иной адрес — отказ при старте.
- `agr:serve-no-write` — **Сервер не пишет**: наружу — только читающие
  инструменты; `edit_messages`, transform и движение вида (`apply_filter`,
  `goto`, `set_columns`…) вычеркнуты из списка, по имени — отказ.
- `agr:serve-events` — **Скан — запуск с номером.** `search_messages` и
  `count_messages` отвечают `202 {op_id}`; `op_started`, найденное поиском —
  `op_item` по мере скана (`search_each`), `op_finished`/`op_failed` с итогом —
  в SSE (`broadcast` на 1024, отставший получает
  `resync`); итог помнят 50 последних запусков. Остальное — синхронно; всё — в
  `spawn_blocking`, скан не держит ни `/healthz`, ни SSE.
- `agr:serve-stop` — **Ctrl+C и SIGTERM останавливают сервер сразу**: потоки
  SSE (события, кадры видов, сессии MCP) закрываются, вызовы в полёте ждём не
  дольше 10 с, второй Ctrl+C — выход немедленно; долгий скан выход не держит.
- `agr:serve-link-handle` — **Линк — открытый хэндл по url.** Первый вызов с
  url поднимает спул (`io::link`), следующие читают его как файл — свежий на
  момент вызова; не стал Active за 20 с (неверное имя сервиса) — отказ с
  состоянием, спул убран; состояние — событием `link` на каждую перемену; `DELETE` или
  выход сервера спул убирают. FILE или LINK из командной строки — по умолчанию
  для вызовов без `file`; линк открыт сразу, с `--open` и `--keep`.
