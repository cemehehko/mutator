# Архитектура

Уровень под требованиями (`REQUIREMENTS.md`) и брифом (README): карта модулей,
потоки данных и договорённости.
Как устроен каждый модуль — в его `//!` (`cargo doc --document-private-items`).

## Карта

Одна библиотека `tui_patch`, бинарник `mutator` (`src/main.rs`): окно (egui), `--tui` —
терминал (в сборке без GUI — всегда), `--dump` — печать YAML как у tll-read. Файл читает libtll; интерфейс и
чтение говорят только каналами: команды туда, события обратно.

```
   окно egui ──┐     ┌── TUI в окне (F2) ── терминал --tui
   ui/table,   │     │   ui/tui: одна сетка знаков
   detail, bar │     │
               ▼     ▼
            desk.rs: окно строк, фильтр, поиск, деталь, ввод
                  │ Cmd ▲ Ev
                  ▼     │
            data/: воркер окна + фоновые индекс, фильтр, поиск
                  │  куски seq параллельно, свой контекст на поток
                  ▼
            tll/: file:// и lua+file:// через libtll + tll-lua
            decode/ + scheme.rs: тело по схеме → дерево полей
```

| Модуль | Отвечает за |
|---|---|
| `io/` | фасад чтения и записи: бэкенд по файлу и сборке, ленивые контексты, загрузка библиотек |
| `app.rs` | запуск: аргументы, выбор режима — окно, терминал, печать; в библиотеке для внешних бэкендов |
| `tll/` | бэкенд TLL — FFI к libtll: контекст, чтение файла с seq и Lua-фильтром, перенос схемы |
| `scheme.rs` | схема в своих типах: сообщения, поля, enum, bits, пути полей |
| `decode/` | тело сообщения по схеме → дерево [`Node`] и текст значений как у tll-read |
| `lua.rs` | код `tll_filter` для префикса `lua+` — тот же, что строит tll-read |
| `lua_highlight.rs` | подсветка Lua для редактора: токены → цвета, для окна и TUI |
| `range.rs` | границы `-s` и перехода: `SEQ`, `+N`, `-N` |
| `dump.rs` | `--dump`: YAML как у tll-read, `--stat`, цвет, мутации сессии |
| `data/` | воркер: окно строк, разреженный индекс, фильтр и поиск по кускам |
| `columns.rs` | колонки и пресеты (встроенный «orders», свои в `presets.toml`) |
| `desk.rs` | состояние просмотрщика — одно на все виды; клавиши и строки ввода |
| `session.rs` | сессия файла: фильтр, поиск, колонки, место, деталь, окно — по имени файла |
| `recent.rs` | последние открытые файлы: список в `recent.toml`, последний существующий |
| `edit/` | правки полей через tll-patch и фиксация в новый файл или с бэкапом |
| `agent/` | диалог с моделью: настройки и диалоги на диске, клиент к LLM, инструменты чтения датника |
| `markup.rs` | разбор ответа модели на блоки (`Block`) и спаны (`Span`), общий для окна и TUI |
| `ui/` | окно: таблица, деталь, панель; `ui/shell.rs` — оболочка (заглушка, смена файла, перетаскивание), `ui/menu.rs` — родное меню macOS; `ui/tui/` — сетка знаков и терминал; `ui/agent/` — экран агента |

`ui/` режется по деталям, как в black-d: таблица, деталь, панель, раскладка
колонок, тема; страница окна только собирает. TUI — подсистема со своей сеткой,
но тем же `Desk`.

## Потоки

- **Окно строк.** `Desk` держит строки вокруг экрана с запасом; у края запаса
  просит воркер дочитать (`Extend`), дальний край обрезает. Прыжок (Home, End,
  `g`, полоса прокрутки, найденное) — новое окно с новым поколением; устаревшие
  ответы отбрасываются, очередь воркера сжимается до последнего прыжка.
- **Индекс.** Сразу после открытия, параллельно по кускам seq: число строк,
  контрольные точки (строка, seq) и счётчики типов. До индекса номера строк
  нет, полоса прокрутки — по seq.
- **Фильтр.** Код Lua как у tll-read; скан по кускам, найденные seq растут
  префиксом в общем `Matches`, таблица показывает их сразу. Вид фильтра — окно по
  номеру строки в `Matches`.
- **Поиск.** То же выражение, пересечённое с фильтром; куски растут от выбранной
  строки, первое совпадение в нужную сторону — ответ.

## Договорённости

У каждой — id: им помечены держащие её тесты и код; `scripts/trace.sh` следит,
чтобы ни одна не осталась без теста, а метка — без договорённости. «Без теста» —
осознанное исключение с причиной.

### Данные

- `agr:same-as-tll-read` — **Значения — как у tll-read.** Разбор и `--dump`
  сверяются с python-tll на эталонах и живых файлах: Decimal, время, enum,
  строки, кавычки YAML.
- `agr:lua-like-tll-read` — **Фильтр — код tll-read.** `tll_filter` строится
  строка в строку как `tll-read -f/--message`; выполняет его tll-lua, не мы.
- `agr:backend-choice` — **Бэкенд — по файлу и сборке.** `--backend`, иначе бэкенд
  открытого файла (`Info`), иначе первый бэкенд, узнавший начало файла.
- `agr:io-facade` — **Остальной код не знает бэкенда:** всё — через `io/`.
  Без теста: устройство модулей, его держит сборка каждой фичи по отдельности.
- `agr:backend-dlopen` — **Библиотеки бэкендов грузятся при открытии**, не
  линкуются; путь канонизируется — вторая копия раздвоила бы журнал и модули.
- `agr:backend-plugin` — **Внешний бэкенд — через `io::register`** до
  `app::main`: свой Lua-диалект, печать `--dump` и библиотека; основная репа о
  нём не знает.
- `agr:dump-first` — **`--once` — одно сообщение.** `--dump --once` печатает
  первое сообщение выборки, включая выборку с пропуском (`+N:`).
- `agr:dump-color` — **Цвет — как у tll-read.** Красит только `Painter`,
  эталонный вывод — без ANSI; `--color auto` — только когда вывод в терминал.
- `agr:dump-stat` — **`--stat` — meta-проход.** Границы seq, всего сообщений
  и счётчики типов без чтения тел.
- `agr:dump-mutations` — **`--dump` показывает сессию.** Фильтр, правки и
  включённый transform применяются (`patch+lua+file`), изменённые поля помечены
  `# в файле: <старое>`; при transform фильтр едет как в виде — пост-эвалом
  (`agr:filter-post-eval`), без — кодом в канале, как у tll-read. `--fresh`
  читает сырой файл.
- `agr:transform-shadow` — **Вид показывает тело после мутатора и отмечает
  отличия от файла.** При transform чтение тел идёт `patch+[lua+]file://` без
  пресета фильтра: тела едут в вид уже прогоными — как на фиксации. Диф мутатора
  считается второй читкой: те же seq читаются сырыми из файла и прогоняются
  через пару `lua+direct` постом в direct-slave (синхронно). Отличившиеся поля —
  красные, в подсказке — значение из файла; поменял seq — строка красная, в
  деталях рядом исходный seq (правки адресуются им); выброшенное мутатором
  сообщение в вид не попадает вовсе. Ошибка мутатора не ломает вид и видна в строке
  состояния. Фильтр и поиск едут по правленному потоку с пост-эвалом
  (`agr:filter-post-eval`), фиксация — полный `patch+[lua+]file://` (ручная
  правка поверх мутации скрипта).
- `agr:filter-post-eval` — **Фильтр и поиск едут по правленному потоку.** Чтение
  — `patch+lua+file`; типы отбираются в Rust по msgid (meta-оптимизация живёт
  только для отбора одних типов), выражение — пост-эвалом парой `tll_filter`
  (`lua+direct`, `Transformer::filter`) поверх прогоных тел. Transformer — один
  на поток-воркер (`chunks::run_state`), не на кусок. Масс-скан — по сырому
  потоку.
- `agr:bad-message` — **Сломанное сообщение не роняет ни разбор, ни экран.**
  Ошибка — у своего узла; соседние поля видны.
- `agr:missing-field` — **Поля нет в типе — ячейка пустая**, в фильтре — `nil`
  по правилам Lua.
- `agr:patch-path` — **Путь поля — в формате tll-patch** (`header.status`):
  деталь показывает его, колонка добавляется по нему. Задел под правку.
- `agr:tll-lifecycle-lock` — **Создание и удаление каналов и контекстов libtll —
  под общим замком**: счётчики ссылок логгеров в libtll неатомарны. Чтение идёт
  параллельно.

### Большие файлы

- `agr:anchor` — **Положение — сообщение, а не номер строки.** Номер появляется,
  когда готов индекс или в виде фильтра; до того листание и прыжки идут по seq.
  Возврат к сообщению (сессия, `g`) показывает его с третью экрана контекста
  выше (`At::Around`), а последнее — у нижнего края: окно, дочитанное до конца
  файла, не оставляет пустоты под последней строкой.
- `agr:reload` — **Растущий файл перечитывается по запросу.** `r` (или `↓`/`PgDn`
  на последней строке) переоткрывает файл на том же месте: курсор остаётся на
  прежнем seq (или ближайшем после него), окно — там, где было; а `End` с
  последней строки перечитывает и встаёт на новую последнюю. В строке
  состояния — сколько дописалось («+N строк»). Фильтр, поиск, колонки, правки и
  transform возвращаются из сессии.
- `agr:sparse-index` — **Индекс разреженный:** точка на 1024 сообщения, память
  не зависит от размера файла линейно по байтам.
- `agr:chunks` — **Долгое — кусками seq параллельно**, результаты по порядку
  кусков: префикс растёт ровно, поиск отдаёт ближайшее, не дожидаясь остальных.
- `agr:filter-streams` — **Фильтр показывает найденное сразу**, не дожидаясь
  конца скана; выбор возвращается туда, где стоял, когда скан до него дойдёт.
- `agr:ui-no-wait` — **Кадр не ждёт диска.** Всё чтение — в воркере и фоновых
  потоках. Без теста: это устройство каналов, а не поведение экрана.

### Правка

- `agr:patch-overlay` — **Правки накладываются через tll-patch**: файл не меняется,
  вид читает через `patch+file://` с yaml (с transform — `patch+[lua+]file://`,
  правка поверх мутации скрипта), каждая версия правок — новый временный
  файл.
- `agr:edit-checked` — **Значение проверяется до принятия**: воркер прогоняет
  одно сообщение через tll-patch; не принятое — строка ввода возвращается,
  правка не создаётся.
- `agr:edits-in-session` — **Незафиксированные правки — в сессии файла**:
  отложенный `w`, перезапуск не теряет сделанного.
- `agr:commit-keeps-original` — **Фиксация не теряет исходник**: новый файл —
  исходник не тронут; перезапись — исходник в бэкап под свободным именем.

### Агент

- `agr:agent-same-desk` — **Агент работает на том же `Desk`, что и человек.**
  Читающие инструменты идут в своём потоке, а фильтр, поиск, переход, колонки и
  правки агент не делает сам: он шлёт действие по каналу, и его применяет вид —
  как если бы это нажал человек.
- `agr:agent-snap` — **Агент видит состояние вида через снимок.** Вид при каждом
  `poll()` отдаёт воркеру снимок (что открыто, фильтр, колонки, выбор) —
  читающие инструменты отвечают по нему, не опрашивая вид синхронно.
- `agr:agent-sync` — **Правки агент показывает один раз.** Посмотрев
  незафиксированные правки, агент отмечает их просмотренными — вид перестаёт
  присылать их в каждом снимке.
- `agr:agent-batch` — **Правка — пачка с одним подтверждением.** Один вызов
  `edit_messages` собирает всю пачку: записи проверяются по текущим значениям
  полей и прогоном tll-patch до показа, человеку уходит одна сводка
  с количеством сообщений, и одно решение применяет или отбрасывает пачку
  целиком одним действием. Негодная пачка возвращается модели отказом —
  человека она не тревожит.
- `agr:agent-no-write` — **Агент не пишет файл.** Правки он только готовит:
  пачка проходит тот же tll-patch, что и ввод человека, и ложится в
  незафиксированные; фиксацию открывает и подтверждает человек (`w`, Enter).
- `agr:agent-one-turn` — **Один ход за раз:** пока модель отвечает или ждёт
  подтверждения, новый вопрос встаёт в очередь, а команды, меняющие активный
  диалог, пропускаются.
- `agr:agent-queue` — **Вопрос не теряется, пока модель отвечает.** Уточнение
  уходит в очередь с заметкой в ленте; когда ход закончится, накопленное
  склеивается в одно сообщение и ход запускается сам. Прерывание
  (`Ctrl+A`) на подтверждении — отказ с причиной: модель прекращает начатое.
- `agr:agent-gen` — **Правка агента не попадает в чужой файл.** При каждом
  переоткрытии (`Desk::reopen`) поколение файла растёт; правка несёт
  поколение на момент вызова, и устаревшую вид отбрасывает с сообщением —
  вместо молчаливой правки по устаревшей картине.
- `agr:agent-jsonl` — **Диалог пишется после каждого сообщения и обрыв не
  теряет ответ.** Дневник — строка меты и по строке на сообщение: переписка
  дописывается в конец, оборванная строка не читается. Частичный ответ при
  обрыве сети сохраняется в ленту, прежний цельный `.json` ещё читается.
- `agr:agent-tool-pairing` — **Вызов и его результат парные и идут подряд.**
  Результат инструмента сразу в лог как парный `Tool`; при сборке запроса
  непарные вызовы закрываются заглушками (лог не переписывается), а при обрыве
  хода заглушки дописываются в лог. Результат без исполнения — отказ и
  прерывание — тоже ложится парой.
- `agr:agent-loop` — **Воркер отвечает всегда.** Стрим модели идёт в отдельной
  задаче: куски и итог приходят каналами, команды `Confirm`/`Deny`/`Abort`
  читаются в любой момент. Прерывание снимает задачу и ставит флаг: остаток
  вызовов хода не исполняется, долгие сканы останавливаются между кусками.
  Инструменты в ленте — одна строка сводки, не весь результат.
- `agr:agent-retry` — **Повтор — только пока стрим не начался.** Соединение с
  таймаутом; на ошибку соединения и 429 запрос повторяется (по `Retry-After`,
  иначе экспоненциально), уведомляя интерфейс; после первого кадра ответа
  повторов нет — там только прерывание. Живой стрим держит idle-таймаут на
  кадр: общий таймаут убил бы длинный ответ.

### Разметка ответа модели

- `agr:markup-shared` — **Разбор ответа модели общий для окна и TUI.**
  `markup.rs` разбивает текст на блоки кода, списки, цитаты и обычные абзацы,
  а внутри — на спаны жирного, кода и ссылок; оба вида рисуют одну и ту же
  структуру, но своими средствами вывода.

### Вид

- `agr:open-without-file` — **Окно открывается без файла и меняет файл на ходу.**
  Без аргумента окно берёт последний существующий файл из `recent.toml`; нет
  такого — диалог выбора на первом кадре; закрыли ничего не выбрав — заглушка с
  подсказкой. Файл можно сменить меню «Файл» (диалог, «Последние») или
  перетаскиванием в окно; смена строит `App` заново (агент привязан к файлу при
  старте), сессия прежнего пишется, у нового своя. Идёт фиксация — не меняем.
  Только окно: `--tui`, `--dump`, `--stat` без файла по-прежнему просят его.
  Меню и диалог — только macOS (`muda`, `rfd`); в других системах — перетаскивание.
  Системные меню и диалог проверяются руками, остальное — `tests/shell.rs`.
- `agr:gui-detach` — **Окно не держит терминал.** Из терминала оно перезапускает
  себя потомком в своей группе процессов, без ввода-вывода (`--gui` — окно без
  отсоединения, `--foreground`/`-F` — то же для обычного запуска); родитель выходит сразу. Не отсоединяем: `--tui`, `--dump`, `--stat`,
  снимок окна (`MUTATOR_SHOT`), запуск не из терминала (`.app`, скрипт), файл не
  найден (ошибку видно в терминале). Без терминала вовсе — `scripts/bundle-macos.sh`
  собирает `mutator.app`. Открытие файла из Finder («Открыть с помощью») пока не
  поддержано: winit 0.30 не отдаёт событие открытия документа — файл берут
  перетаскиванием в окно или из меню.
- `agr:session-by-name` — **Сессия привязана к имени файла**, а не к пути: копия
  со стенда открывается с теми же фильтром, колонками и местом. Пишется при
  изменении и при выходе; `--fresh` — начать с чистого листа.

- `agr:detail-share` — **Высота детали — доля окна**, одна для окна и TUI и в
  сессии: `{`/`}` и сессия её задают, панель окна следует за ней (в том числе
  при пустой детали и после правки поля), а тянут границу — доля берётся из
  фактической высоты.

- `agr:tui-same-data` — **TUI — другой вид того же `Desk`**: в окне (F2) и в
  терминале одни клавиши, один ввод, одно состояние.
- `agr:tui-grid` — **TUI — сетка: знак в своей клетке**, шрифт не сдвигает
  столбцы (из black-d).
- `agr:gui-lua-text` — **Код редактора Lua виден в окне.** Панель номеров строк
  занимает ровно свою ширину, а не всю: поле ввода не схлопывается в нулевую
  ширину, и его текст рисуется подсвеченным.
- `agr:repaint-on-event` — **Окно рисуется по событию воркера**, а не по
  таймеру; пока идёт фоновая задача — не чаще 10 раз в секунду. Без теста:
  перерисовку решает eframe.
- `agr:term-quiet` — **В терминале журнал — в файл**: stderr лёг бы поверх
  экрана. Без теста: нужен настоящий терминал.
- `agr:term-restore` — **Терминал возвращается в прежний вид** при любом выходе и
  панике. Без теста: нужен настоящий терминал.

## Проверки

`scripts/check.sh` — одна точка входа, в Docker (образ собирает tll и tll-lua из
`../tll`, `../tll-lua`): fmt, clippy, тесты (юнит, интеграционные на эталонах
`tests/data`), документация без битых ссылок, сценарии и требования
(`scripts/req.sh`), трассировка договорённостей, уровни описания и порог
покрытия по модулям карты. Порог только поднимается.

Эталоны пишет `scripts/golden.py` (python-tll); живой файл сверяется так же
(`MUTATOR_GOLDEN`). Замер на больших файлах — `examples/bench.rs`, файл для
него — `scripts/bigfile.py`.
